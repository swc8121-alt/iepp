# TRP 2.0 Research Abstract

The Trajectory Reconstruction Problem (TRP) asks whether an adversary that observes, copies or compromises an execution lineage can produce an unauthorized future continuation that a continuity verifier accepts as canonical. TRP 2.0 replaces a divergence-centric formulation with a canonical-continuation security game. The model explicitly parameterizes attacker knowledge, compromise timing, signing authority, entropy influence, verifier influence, registry behavior and evidence level. This avoids treating stochastic fork divergence as proof of originality: independent fresh inputs can make cloned executions diverge without identifying either branch as canonical.

Applied to IEPP, the primary event is unauthorized canonical acceptance. Replay, stale-predecessor rollback, wrong-key forgery and dual acceptance in a single-successor registry are expected to fail under their stated assumptions, while compromise of both current signing authority and current state is retained as an explicit software-level boundary control. The accompanying validation framework separates protocol invariants, cryptographic assumptions, platform assumptions, empirical attack results and unproved hardness conjectures. This formulation is intended to support falsifiable benchmarking today and a future reduction-based treatment of selected IEPP variants.
