IEPP A3: initial VirtualBox snapshot and fork results

Four two-branch trials each recorded one accepted successor. A separate submission after an actual VM rollback was rejected.

This update adds five cases and nine client records from a Windows-hosted registry and Ubuntu VirtualBox clients. In the shared-challenge serial case, the server records agree with both client results.

What the evidence supports

Within the observed runs, a single online registry maintained one accepted continuation under its declared policy. The protected action was simulated, and the application cooperated with the registry decision.

B won when submitted first. These results therefore do not identify an intrinsic or physical original. They do not establish entropy quality, malicious-hypervisor resistance, hardware-backed L2, production readiness or complete A3 coverage.

Next steps

Complete provenance and earlier server-log collection; add approved-state snapshot export and server timing observations; test snapshots after an accepted transition, shared-challenge reverse order and explicit restore; then run a predefined competing-submission matrix. Entropy fault injection and hardware-backed L2 entry criteria remain separate work.
