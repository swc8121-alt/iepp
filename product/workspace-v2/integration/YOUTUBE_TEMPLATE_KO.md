# IEPP Workspace v2 — 유튜브 콘텐츠 제작 템플릿 (PR #22 보완)

상태: **정적 체험판 + 추천안 데이터 생성 코드**, 운영 사이트 미배포, 실제 계정에 등록·승인·실행 없음.

## 고객 경험
1. 홈에서 "유튜브 채널의 콘텐츠를 기획하고 제작하고 싶어요" 입력 또는 "▶️ 유튜브 채널" 선택.
2. 프로젝트명과 목표 검토. 자동 감지는 `유튜브`, `youtube`, `유투브`, `쇼츠`, `shorts`, `영상` 포함 시 유튜브 템플릿을 우선 선택.
3. 추천안 확인: 총괄 1 + 전문 역할 3 = **4개 AI 역할**, 작업 초안 **6개**.
4. 체험 버튼을 누르면 브라우저 메모리에만 프로젝트 초안 1개, 역할 4개, 작업 6개 추가. 서버 저장/승인/모델 실행/게시 없음.
5. 작업 센터의 **미실행 초안** 탭에서 작업 6개를 확인.

## AI 역할
- 콘텐츠 총괄 AI: 채널 방향, 검토 및 승인 대기
- 트렌드 조사 AI: 조사 계획, 주제 후보, 출처 구분 (실시간 트렌드 주장 금지)
- 대본 작성 AI: 일반 영상 2편, 쇼츠 4편 대본 초안
- 제작·운영 AI: 촬영·편집 지침, 제목/썸네일 문구 (실제 업로드 없음)

## 작업 초안 6개
1. 채널 콘셉트 후보와 대상 시청자 검토 — 총괄
2. 콘텐츠 아이디어 10개 및 출처 조사 — 조사
3. 일반 영상 2편·쇼츠 4편 대본 초안 — 대본
4. 촬영·편집 지시서 및 썸네일 문구 — 제작·운영
5. 최종 검토 및 사용자 게시 결정 요청 — 총괄
6. 실제 게시 후 관측 지표가 있는 경우에만 성과 보고 초안 — 총괄

## 프로그램 인터페이스 및 안전 경계
`integration/recommendation-contract.mjs`에 `youtube` 사전 구성 키를 추가하고, 공식 `save_project_recommendation` 입력 형식으로 검토용 초안 payload를 생성할 수 있게 했다.

**연결 순서에는 변함이 없다:** 운영 사이트가 생성한 실제 `draft_id` → `get_project_recommendation_request`에서 revision/목표 확인 → payload 구성 → `save_project_recommendation`로 pending 초안 저장 → 사용자가 운영 사이트에서 직접 검토·생성.

이는 운영 환경에서 요청 생성 API 경로/사이트 소스가 확인되기 전까지 준비 코드이며, 임의 엔드포인트나 자동 실행은 추가하지 않았다. `model_label`은 추천 표시이므로 실제 모델 인스턴스를 뜻하지 않는다. IEPP 레지스트리 기록 일치는 런타임 동일성·물리적 원본성의 증명이 아니다.

## 실제 확인
- Node.js v22, `node --test`: **10개 테스트 전부 통과**.
- HTML 인라인 JavaScript `node --check` 통과.
- Chromium: PC 1440×960 및 모바일 390×844에서 템플릿 선택 → 4개 역할/6개 작업 미리보기 → 체험 초안 생성 → 작업 센터 초안 6건 표시 테스트 통과, JavaScript 페이지 오류 없음, 모바일 가로 넘침 없음.
- 일반 문장 입력 후 유튜브 템플릿 자동 선택도 별도 확인.
- 이 테스트는 네트워크/실서버 통합 테스트가 아님.

## 남은 작업
실제 운영 사이트의 소스 및 배포 경로 연결, 요청 생성 및 조회 계약 확인, 계정별 저장/재접속/E2E/승인 경계 테스트, 비용·보관 정책 확인이 선행되어야 실제 사용자 프로젝트를 안전하게 생성할 수 있다.
